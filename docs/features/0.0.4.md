# 🚀 Versão 0.0.4 — Física (Rapier) e Character Controller

O objetivo desta versão é dar **peso e colisão** ao personagem: gravidade, repouso
no chão, colisão com obstáculos estáticos, subida de rampas e degraus, e pulo.

A física entra via **Rapier headless** (`@dimforge/rapier3d-compat`, WASM), rodando
dentro do passo fixo da simulação. O `movementSystem` deixa de mover o `Position`
diretamente — ele só produz a velocidade desejada; quem resolve o movimento contra
o mundo é o character controller do Rapier.

> Versionamento: mantém o esquema `0.0.x` (ver nota em `0.0.2.md`).

---

## Contexto (o que o 0.0.3 deixou)

- `movementSystem` (core) calcula `Velocity.x/z` a partir do input + yaw da câmera
  **e integra direto em `Position`**. `Velocity.y` existe mas não é usado.
- Não há gravidade, chão sólido nem colisão. O personagem desliza num plano.
- `GameScene` desenha um plano `50×50` e um grid, sem colliders.

## Decisão de arquitetura (registrada aqui)

- **Rapier só é importado dentro de `src/core/physics/`.** Nenhum outro módulo —
  e principalmente a camada view — importa a lib. Todo o resto fala com a física
  por uma API fina desse pacote. Rapier-compat é WASM puro (sem DOM), então
  `core/physics/` continua headless e portável para servidor/worker.
- Isto ativa e refina o item "Ao escolher física" da doc de regras
  (`docs/rules/README.md`), que será atualizada.
- **Sem heightfield / terreno procedural nesta versão.** O relevo de teste são
  obstáculos estáticos (rampa, degraus, plataforma, parede) definidos em um único
  dado compartilhado que alimenta física e render — garantindo que o visível bate
  com o colidível. Terreno com altura contínua fica para quando a geração
  procedural começar.
- **Sem colliders com escopo de chunk ainda** (não há chunks). Os colliders
  estáticos são criados uma vez no bootstrap.
- **Sem eventos de colisão.** O character controller resolve a colisão com
  obstáculos internamente; nenhum evento é necessário nesta versão.
- **Só corpo cinemático + estáticos.** Nada de corpos dinâmicos (caixas que caem,
  empilhamento, ragdoll).

---

## Objetivos

- Integrar Rapier headless, isolado em `src/core/physics/`.
- Modelar o corpo do personagem como cápsula cinemática com `KinematicCharacterController`.
- Gravidade e estado "no chão" (`Grounded`).
- Pulo com altura configurável, só a partir do chão.
- Colisão com obstáculos estáticos; subida de rampas e auto-degrau.
- Cenário de teste (rampa, degraus, plataforma, parede) vindo de um dado único.
- Manter o core headless e testável sem React/Three/DOM (Rapier roda em Node).

## Critérios de Conclusão

- O personagem cai da posição inicial e **repousa** no chão.
- Andar contra a **parede/caixa** é bloqueado; o personagem desliza ao longo dela.
- A **rampa** é subida sem travar; o **degrau baixo** é transposto automaticamente.
- O **degrau alto** só é vencido com **pulo** (`Space`); pular só funciona no chão.
- Sobre a **plataforma**, o personagem anda normalmente e cai ao sair da borda.
- `Velocity.y` é resetado ao tocar o chão (não acumula gravidade indefinidamente).
- Nenhum módulo fora de `src/core/physics/` importa `@dimforge/rapier3d-compat`.
- `core/` (incl. `core/physics/`) roda headless — teste em Node inicializa o Rapier,
  cria chão + obstáculos + personagem e valida queda, colisão e rampa.
- Visual dos obstáculos bate com os colliders (mesmo dado `TEST_LEVEL`).
- `npm run build` e `npm run lint` passam.

---

## Riscos e pontos de atenção

- **Init assíncrono do WASM.** O world e os corpos só existem depois de
  `initPhysics()`. Tratado com early-return nos systems + bootstrap tardio. Uma
  tela de loading via `<Suspense>` pode vir depois se o "congelar por ~50ms"
  incomodar.
- **HMR do Next.** Recriar o world a cada hot-reload pode vazar WASM; `disposePhysics()`
  no cleanup e a flag de bootstrap idempotente mitigam.
- **Passo fixo × `computeColliderMovement`.** O KCC precisa ser chamado uma vez por
  passo fixo, antes do `world.step()`. A ordem dos systems na fase `simulation` é
  parte do comportamento — está fixada na etapa 10.
- **Tuning do controller** (slope, autostep, snap) provavelmente vai precisar de
  ajuste fino no browser. Tudo em `GAME_CONFIG.PHYSICS`.
